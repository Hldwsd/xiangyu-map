# 底图数据说明（public/maps/anhui.json）

ECharts 从 5.0 起不再内置地图数据（见 [官方 FAQ](https://echarts.apache.org/zh/faq.html)），
所以底图由本项目自己提供，放在 `public/maps/anhui.json`，运行时按需下载，不打进 JS bundle。

底图是**安徽省的市级轮廓**：16 个要素，每个要素就是一个地级市的边界与名称，
地图上的分区与市名直接来自这里，不需要另画图层。

## 来源与生成方式

| 项           | 值                                                                                   |
| ------------ | ------------------------------------------------------------------------------------ |
| 来源         | 阿里云 DataV.GeoAtlas `https://geo.datav.aliyun.com/areas_v3/bound/340000_full.json` |
| 正式获取方式 | `pnpm data:anhui-map`（`scripts/fetch-anhui-map.mjs`）                               |
| 要素数       | 16（安徽省 16 个地级市，全部 `level=city`）                                          |
| 体积         | 原始 124.3 KB / gzip 39.8 KB（预算 250 KB）                                          |
| sha256       | `7ca3290e0458f34086df4d61fa9804e2c624d55dfe5f8f6a841844b5dcd43207`                   |
| 抓取时间     | 2026-11-19                                                                           |

16 个市的 adcode：340100 合肥市、340200 芜湖市、340300 蚌埠市、340400 淮南市、340500 马鞍山市、
340600 淮北市、340700 铜陵市、340800 安庆市、341000 黄山市、341100 滁州市、341200 阜阳市、
341300 宿州市、341500 六安市、341600 亳州市、341700 池州市、341800 宣城市。
（没有 340900：这个编码段不是地级市。）

要更新底图就重跑 `pnpm data:anhui-map`，它会把上面的体积与 sha256 重新打印出来；
提交时请同步更新本文件的表格。脚本会断言要素数为 16、层级全为 `city`——
抓成不带 `_full` 的 `340000.json` 时只有省界、没有市级轮廓，页面会「看着有图但分区全丢」。

## ⚠️ 上线前必须处理（合规）

这是**内部演示用**的示意底图，不是可直接公开的互联网地图：

1. 公开登载地图（含省级地图）需要经过地图审核并标注**审图号**（《地图管理条例》、自然资源部与工信部相关规定）。
   M0 阶段先跑通渲染，**公开上线前必须换成有审图号的权威底图服务**，或完成送审。
2. 底图为示意轮廓，边界以官方发布为准；不得作为行政边界、领土主张的依据。
3. DataV.GeoAtlas 数据的使用条款请以阿里云官方说明为准；若上线，需确认商用授权范围。

相关依据：自然资源部《地图管理条例》宣传页
<https://f.mnr.gov.cn/202105/t20210510_2631406.html>；新华/光明网报道
<https://m.gmw.cn/2024-05/13/content_1303736179.htm>。

## 与项目坐标的关系

`src/data/sites.ts` 里的坐标统一按 GCJ-02 记录，并且必须落在
`src/utils/region.ts` 的 `ANHUI_BBOX`（114.8–119.75°E / 29.3–34.75°N）内。
底图轮廓与坐标的坐标系一致性，在换成权威底图时需要一并核对（不同来源的偏移会造成地标与地形错位）。
