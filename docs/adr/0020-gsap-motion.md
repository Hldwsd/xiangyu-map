# 0020. 主应用动效用 GSAP（按需加载）

- 状态：已接受
- 日期：2026-11-23
- 决策人：A

## 背景

品牌页（`/brand/`）已经在用 GSAP + ScrollTrigger 做滚动叙事；主地图应用此前是纯 CSS 过渡，
选中卡片、列表抽屉、空状态都是「瞬间出现/消失」，交互感偏硬。GSAP 已在
`package.json` 依赖里（品牌页用），主应用接入不会新增依赖，只需控制它对首屏预算的影响。

## 决策

主应用按需使用 GSAP，统一走 `src/utils/motion.ts`：

- **动态 `import('gsap')`**：第一次需要动画时才加载（独立 chunk，约 27.5 KB gzip），
  入口 JS 只增加约 2.6 KB（261.66 → 264.28 KB，预算 300 KB）；
- 目前覆盖：选中卡片入场/退场（含封面从 1.05 收回）、列表抽屉滑入、空状态淡入、封面鼠标视差（精确指针设备，±6px）；
- 城市索引 hover 用 ECharts geo region 高亮（描边加粗、轻市域加深），不占用动效预算；
- `prefersReducedMotion()` 时**不加载 gsap**、直接 `done()`，退化成原来的瞬时切换；
- 动画时长控制在 160–340ms，`power2/power3`，不做弹跳与无限循环。

## 理由

- 比 CSS keyframes 更容易做「退场 + 完成回调」和错峰；`clearProps: 'transform'` 避免残留
  transform 影响 `position: fixed` 的浮层；
- 按需加载让首屏预算几乎不动，品牌页的重动效不拖累地图；
- 动效只服务「状态变化」，不加装饰性 hover 动画，避免和地标小球物理抢注意力。

## 代价

- 首次交互会多一次 chunk 请求（约 70 KB 原始 / 27.5 KB gzip），弱网下动画会晚 ~100ms 或直接走无动画；
- 多一个需要维护的 `motion.ts` 入口（加载失败、减少动效、SSR 都走安全分支）。
