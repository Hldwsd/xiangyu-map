# 0022. 分享图集：WebGL 横向卡带 → 安徽地图矩阵

- 状态：已接受
- 日期：2026-11-24
- 决策人：项目所有者（发起）、实现方

## 背景

站内已有 70 张分享卡（`src/data/sites.ts` 的 `shareImage`，`public/og/sites/<id>.jpg`）。
需要一页能「看见全部 70 张」的图集，并且不是普通瀑布流：先由十张精选做一段有记忆点的
WebGL 滚动叙事，再让全部照片拼成安徽省地图。

## 决策

- **独立路由 `/gallery`**，Vue 视图按需加载（`src/views/GalleryView.vue`），
  GSAP 仍走动态 `import`，不进入首屏预算。
- **自写 WebGL，而不是 Three.js**：场景里只有一种弯曲平面、一个着色器、70 次 draw call，
  自写投影/模型矩阵即可；省掉一个 150 KB+ 的渲染引擎，也不和 GSAP 抢 rAF。
- **横向 3D 卡带（不是竖螺旋）**：
  - 十张精选排成一条横向卡带，C 位 `1.56` 宽、两侧 `1.42`；两侧卡向中间转 `0.24 rad`、
    后退 `0.55`，越远越淡，形成一层层向中间收的扇形；
  - 滚动只改 `slide`（0→9），卡带向左滑，下一张从右侧进入中心；C 位始终在画面中心；
  - **入场只画 C 位**：`intro = 0` 时 C 位是一张平卡（`curve = 0`），其余卡片和倒影透明；
    向下滚时 C 位先弯成凸面，整条卡带淡入，然后才开始滑；
  - 每张卡下面有一层很淡的倒影（同一纹理上下翻转、透明度 0.08–0.16），把卡带「放」在暗场里；
  - 刻意不再做竖螺旋：十张卡绕一圈时，正面只剩两三张，侧看就是一条斜线，读不出螺旋。
- **曲面照片**：平面 18×11 段，顶点着色器把局部 x 弯成**凸**弧
  `z = uCurve * (0.25 - x²)`（中心朝向镜头），并用法线做轻微明暗；
  卡带段 `uCurve ≈ 0.22`，地图段压到 `0.08`，只保留纸片的弧度。
- **安徽地图矩阵**：
  - 全部 70 张照片对应一个 5×14 的网格，网格铺满地图范围；
  - 用 `PROVINCE_OUTLINE` 画一张 480×707 的遮罩纹理，片元着色器按世界坐标取遮罩，
    网格被裁成安徽省轮廓；遮罩边缘通过邻域采样补一圈金线；
  - 当前 C 位的网格位置与中央格交换，保证选中的图片落在图中心；
  - 相机从卡带的 `5.4` 缓慢推近到 `4.5`。
- **GSAP**：一条 ScrollTrigger 时间线，pin 住舞台；0–0.12 入场（C 位变凸、卡带淡入），
  0.14–0.54 滑动，0.55–0.9 进入地图；引擎按 `intro / slide / map` 三个状态插值。
- **降级**：窄屏 / `prefers-reduced-motion` / WebGL 不可用时，不做 pin 与 3D，
  直接渲染 4 列全量矩阵（同一份数据）。
- **可达与直达**：`scripts/prerender-sites.mjs` 额外生成 `dist/gallery/index.html`；
  顶栏与菜单加入口；WebGL 场景外提供 70 条屏幕阅读器链接。

## 理由

- 横向卡带比竖排螺旋更容易读：C 位永远明确，左右有上下文，滚动方向与「翻下一页」一致。
- 曲面的关键观感用顶点着色器实现，CSS 3D 只能做整块平面 rotate，做不出照片内部弯曲。
- 不自写渲染器而用 Three.js 也能做，但这一页只有平面与一种遮罩，Three 的
  Scene/Camera/Renderer/材质体系反而是额外的心智与体积成本。
- 用省界遮罩而不是把 70 张图按点采样进轮廓：5×14 的矩形网格边缘会被遮罩逐像素裁切，
  轮廓更干净，也不需要解决「70 个采样点怎么均匀铺满省界」的问题。

## 代价

- 70 张 512×269 纹理约占 38 MB 显存；纹理在进入页面后按 8 路并发加载，
  弱网下矩阵会先出现深色底再逐张填满。
- 十张卡带的倒影让 draw call 从 70 涨到约 80，但仍在预算内。
- 5×14 网格是按 70 张固定的；分享图数量变化时要同步调整网格与中心格。
- 3D/曲面只在桌面启用；窄屏直接给静态矩阵。

## 备选方案

- **竖螺旋**：先做过，十张卡绕一圈时正面只剩两三张，看起来是一条斜线而不是螺旋；
  除非把卡片缩得很小、再补一条引线，否则读不出来，已放弃。
- **Three.js**：开发快，但多一个 150 KB+ 依赖，首屏预算之外还要维护材质与光照。
- **CSS 3D**：实现简单，但照片无法曲面弯曲，也做不了逐像素的省界遮罩。
- **2D Canvas + 图片切片**：可以做弯曲，但 70 张图的每帧重绘成本高于 WebGL 纹理。
