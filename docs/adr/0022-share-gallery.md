# 0022. 分享图集：WebGL 曲面竖螺旋 → 安徽地图矩阵

- 状态：已接受
- 日期：2026-11-24
- 决策人：项目所有者（发起）、实现方

## 背景

站内已有 70 张分享卡（`src/data/sites.ts` 的 `shareImage`，`public/og/sites/<id>.jpg`）。
需要一页能「看见全部 70 张」的图集，并且不是普通瀑布流：十张精选先以带曲面弯曲的
3D 竖螺旋出现，往下滚时螺旋转动、把当前图片送到画面中心；再往下，全部 70 张照片飞入
一个矩阵，最后拼成安徽省地图。

## 决策

- **独立路由 `/gallery`**，Vue 视图按需加载（`src/views/GalleryView.vue`），
  GSAP 仍走动态 `import`，不进入首屏预算。
- **自写 WebGL，而不是 Three.js**：场景里只有一种弯曲平面、一个着色器、70 次 draw call，
  自写投影/模型矩阵即可；省掉一个 150 KB+ 的渲染引擎，也不和 GSAP 抢 rAF。
- **曲面照片**：平面 18×11 段，顶点着色器把局部 x 弯成弧
  `z = uCurve * (x² - 0.25)`，并用法线做轻微明暗；螺旋段 `uCurve ≈ 1.05`，
  地图段压到 `0.08`，照片从卷曲的纸片过渡成墙面。
- **竖螺旋（没有额外预览图）**：
  - 10 张精选按 36° 等角、0.8 世界单位纵向间距、1.8 半径排在 3D 圆柱上；
  - 滚动让圆柱转 324°，当前朝向正面的卡片就是 `active`；整条螺旋按当前卡的 y 反向平移，
    让 active 始终落在画面中心；
  - 不再放第二张「预览大卡」——中间看到的就是螺旋里的那张；底部 HUD 只给名称 / 城市 / 分类。
- **安徽地图矩阵**：
  - 全部 70 张照片对应一个 5×14 的网格，网格铺满地图范围；
  - 用 `PROVINCE_OUTLINE` 画一张 480×707 的遮罩纹理，片元着色器按世界坐标取遮罩，
    网格被裁成安徽省轮廓；遮罩边缘通过邻域采样补一圈金线；
  - 当前 active 的网格位置与中央格交换，保证选中的图片落在图中心；
  - 相机在矩阵段缓慢推近，配合网格落位。
- **GSAP**：一条 ScrollTrigger 时间线，pin 住舞台；0–0.5 旋转，0.55–0.9 进入地图；
  引擎按 `spin / map` 两个状态插值，地图段每张卡再叠一个小的错峰延迟。
- **降级**：窄屏 / `prefers-reduced-motion` / WebGL 不可用时，不做 pin 与 3D，
  直接渲染 4 列全量矩阵（同一份数据）。
- **可达与直达**：`scripts/prerender-sites.mjs` 额外生成 `dist/gallery/index.html`；
  顶栏与菜单加入口；WebGL 场景外提供 70 条屏幕阅读器链接。

## 理由

- 曲面是这次的关键观感，CSS 3D 只能做整块平面的 rotate，做不出照片内部的弯曲；
  用顶点着色器是最短路径。
- 不自写渲染器而用 Three.js 也能做，但这一页只有平面与一种遮罩，Three 的
  Scene/Camera/Renderer/材质体系反而是额外的心智与体积成本。
- 用省界遮罩而不是把 70 张图按点采样进轮廓：5×14 的矩形网格边缘会被遮罩逐像素裁切，
  轮廓更干净，也不需要解决「70 个采样点怎么均匀铺满省界」的问题。
- 去掉中央预览卡后，滚动与选中是同一件事：转到中间的那张就是当前图，
  不会出现「大图已换、螺旋还没转到位」的双份状态。

## 代价

- 70 张 512×269 纹理约占 38 MB 显存；纹理在进入页面后按 8 路并发加载，
  弱网下矩阵会先出现深色底再逐张填满。已验证 70 张全部加载后无占位残留。
- WebGL 场景没有 DOM 语义，额外维护了一份 70 条的屏幕阅读器链接列表。
- 5×14 网格是按 70 张固定的；分享图数量变化时要同步调整网格与中心格。
- 3D/曲面只在桌面启用；窄屏直接给静态矩阵，移动端的「曲面」体验缺席。

## 备选方案

- **Three.js**：开发快，但多一个 150 KB+ 依赖，首屏预算之外还要维护材质与光照；
- **CSS 3D**：实现简单，但照片无法曲面弯曲，也做不了逐像素的省界遮罩；
- **2D Canvas + 图片切片**：可以做弯曲，但 70 张图的每帧重绘成本高于 WebGL 纹理。
