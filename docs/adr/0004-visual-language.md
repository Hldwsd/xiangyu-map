# 0004. 视觉语言基线：token 化与三个候选方向

- 状态：提议（方向待定，选型后本条转「已接受」并删除未选中的两组）
- 日期：2026-11-19
- 决策人：A（Hldwsd）提案，最终方向由两人共同定

## 背景

M1 收尾时项目已经能跑：22 条数据、16 市覆盖、聚合与键盘可达都实测过。但样式层几乎没有决策：

- `main.css` 只有 7 个颜色变量（`--paper/--paper-2/--ink/--ink-soft/--line/--accent/--danger`），没有字阶、间距、圆角、阴影 token；
- 组件里散落着 ~20 处字面量颜色（`#fffdf8`、`rgb(255 253 248 / 82%)`）、圆角写成 4/6/8/10/12/14/16/999 八种值、三处手写阴影；
- 分类颜色只存在于地图的 TypeScript 里（`CATEGORY_COLORS`），CSS 里没有对应变量，注释里提到的 `--cat-*` 其实从未存在。

M2 的清单（详情页图文排版、画廊、位置小图、列表↔地图联动、加载/空/错三态、三档断点）80% 是「长什么样」的决定。**在样式语言没定的情况下先写这些组件，等语言一改就是全部重写。**

同时有两个现在解决不了的约束，决定了这次只能定「基线」而不是「定稿视觉」：

1. **底图合规**：现在用的是 DataV.GeoAtlas 的公开 GeoJSON，只够开发期示意；上线前需要审图号或权威底图。想靠「手绘/插画风地图」撑主题，现在做等于白做。
2. **没有授权图片**：22 条数据的封面全是 `public/images/placeholder.svg`，60 条真实数据还在推进中（#17）。视觉风格高度依赖真实图片的色调与构图。

## 决策

1. 建立 **token 层** `src/assets/tokens.css`：颜色（含 `--xxx-rgb` 三元组用于半透明表面）、字体、圆角、阴影、描边、地图配色、6 个分类色，全部集中定义；组件只引用变量。
2. 用 **同一个 token 名字集合**表达三个候选方向，方向之间只覆盖值：
   - `:root` = A「纸墨乡野」（默认，也是现有视觉的规范化）
   - `[data-theme='b']` = B「徽派几何」
   - `[data-theme='c']` = C「数据图鉴」
3. `src/theme/theme.ts` 提供 `applyThemeFromQuery()`（`?theme=a|b|c` → `<html data-theme>`）与 `readThemePalette()`（从 CSS 变量读分类色与地图配色）。地图仍由 `anhui-map-option.ts` 构建 option，但配色来自 token，**组件代码不随方向变化**。
4. 先按三方向出真实样张（首页 + 详情页，桌面宽度），由负责人选一个；选定后删除未选中的两组，本条 ADR 转「已接受」。

## 理由

- **token 化现在便宜**：默认方向 A 的渲染结果与改造前逐像素一致（同样的色值、同样的圆角），改造是一次可验证的重构，不是重设计。
- **三家共用一套名字**：选型之后删掉两组 CSS 即可，组件不用动；如果每个方向各写一套组件类名，比较成本会落到后面。
- **样张来自真实页面**：用 `?theme=` 在真机上切换，比 Figma 假图更有说服力——字体渲染、地图密度、断点行为都是真的。
- **地图配色也进 token**：分类色是视觉语言的一部分，且与无障碍（色觉障碍用户靠颜色+形状双重编码）直接相关，不能让 CSS 与 TS 各存一份。

## 后果

- `?theme=` 是**内部对比用**的临时入口，选型完成后必须删掉（连同 `theme.ts` 里的 `THEME_IDS` 校验与两组未选中的主题块）。
- 方向 B/C 的分类色与方向 A 不同，切换时地图 canvas 会随之重绘；因为 `readThemePalette()` 在组件加载时读一次，切换主题需要刷新页面（对比流程可以接受）。
- 仍未 token 化的是**间距与字号**：这一轮只收拢颜色/圆角/阴影/字体族，逐处替换间距会拉大 diff 且对方向判断无帮助；等方向定下来、M2 排版开始时一并做。
- 占位图（暖米色 SVG）在 B/C 下会显得突兀——这是「没有授权图片」的直接后果，不是 token 的问题。

## 备选方案

- **不 token 化，直接做 M2**：功能推进最快，但每个组件写完都要在视觉定稿时重做一遍样式。
- **等到真实图片与合规底图到位再定视觉**：最省返工，但 M2 会空转数周，且那时才做 M2 的排版等于同时改结构与视觉。
- **上设计系统库（Element Plus / Naive UI 等）**：省下自研组件样式，但会引入整套组件体积与视觉个性，与「一张地图 + 少量列表卡片」的产品形态不匹配，且首屏预算（300 kB）已经吃掉 231 kB。
- **只做一套方向（不做对比）**：省一天，但第一版视觉通常是错的，改起来比选一个更贵。
