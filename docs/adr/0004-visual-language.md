# 0004. 视觉语言基线：黑白 / 现代简约

- 状态：已接受
- 日期：2026-11-19
- 决策人：负责人（项目所有者）拍板方向；A（Hldwsd）负责 token 化与落地

## 背景

M1 收尾时项目已经能跑：22 条数据、16 市覆盖、聚合与键盘可达都实测过。但样式层几乎没有决策：

- `main.css` 只有 7 个颜色变量，没有字阶、间距、圆角、阴影 token；
- 组件里散落着约 20 处字面量颜色、八种圆角、三处手写阴影；
- 分类颜色只存在于地图的 TypeScript 里，CSS 里没有对应变量。

M2 的清单（详情页图文排版、画廊、位置小图、列表↔地图联动、加载/空/错三态、三档断点）八成是「长什么样」的决定，语言不定就写，等于写完再重写。

## 决策

1. **方向：黑白 / 现代简约**。整站只有黑、白、灰三档；层级由字号、字重、细线与留白建立，不靠颜色。
2. 建立 token 层 `src/assets/tokens.css`：颜色（含 `--xxx-rgb` 三元组用于半透明表面）、字体、圆角、阴影、描边、地图配色、分类色。组件只引用变量。
3. **取消颜色编码分类**：六个分类改用六种形状（圆/菱形/针/三角/圆角矩形/方）区分。这对色觉障碍用户更稳，也让黑白界面不靠彩色点撑着。
4. **强调色 = 墨色**：按钮与选中态用「黑底白字」，不引入第二种色相；错误态同样不用红色，靠文案与结构区分。
5. 地图配色进 token：陆地为 `#f2f2f2`、边界 `#dedede`、市名 `#8c8c8c`、聚合点 `#111111`。

## 理由

- **黑白最不容易过时**，也不会和尚未到位的照片打架：22 条数据的封面现在全是米色占位图，任何暖色主题都会让占位图看着像成品；黑白界面反而让"图片待替换"这件事不那么刺眼。
- **单色把注意力推回内容和地图本身**：这是一个以「看地图找项目」为主的产品，装饰性色彩越少，地标越清楚。
- **形状编码比颜色编码更稳**：之前靠「颜色 + 形状」双通道，现在颜色通道取消，形状成为唯一编码——信息量没有实质损失（本来也不是所有用户都能分辨六种色相），而且黑白界面里所有地标都是同一个墨色，点与点之间没有明度竞争。
- **token 化现在便宜**：改造前后默认渲染一致（同样的色值、同样的圆角），是一次可验证的重构，不是重设计。
- 三个候选方向（纸墨乡野 / 徽派几何 / 数据图鉴）都做过真实样张再被替换掉：纸墨乡野暖度够但个性弱；徽派几何直角+无阴影在列表页容易显硬，且很吃真实照片质量；数据图鉴最清楚但情绪最少。黑白现代简约取的是「最克制、最经得起内容变化」这一档。

## 后果

- **没有第二强调色**：悬停/选中只能靠字重、底色、描边变化表达。实现上按钮、选中 chip 用黑底白字，链接靠下划线。
- **错误态不红**：`--danger` 与 `--accent` 同为墨色，错误必须靠文案明确（如「底图加载失败」+ 重试按钮），不能只靠颜色暗示。这是代价，写在这里以免以后有人以为漏了样式。
- **分类颜色变量保留但同色**：`--cat-*` 六个变量名仍在，值是同一个墨色。这样将来若恢复颜色编码，只改 `tokens.css` 一处，组件与地图 option 都不用动。
- **分类筛选的可读性依赖 chip 文案**：`古镇 5` 这类带数量的 chip 承担了分类说明的职责，图例不再是主要入口。
- **组件描边达不到 WCAG 1.4.11 的 3:1**：卡片分隔线 `#e8e8e8` 对白底只有 1.23:1，表单控件描边用了更深的 `--line-strong: #b0b0b0`（约 2.4:1），仍低于 3:1。这是刻意的取舍——黑白极简靠细线分层，把控件描边做成深灰会毁掉整体气质；补偿手段是控件都有显式标签（「城市」「搜索」）、选中态反转成黑底白字、`:focus-visible` 用墨色 2px 描边（18.9:1）。这条写在这里，是为了以后有人拿无障碍清单核对时知道是「已知偏差」而不是漏改。
- **文字对比度达标**：墨色 `#111111` 对白底 18.9:1；次级文字 `--ink-soft: #6e6e6e` 5.1:1；地图市名 `#767676` 4.5:1——正文与界面文字都在 AA 以上。
- 仍未 token 化的是**间距与字号**：这轮只收拢颜色/圆角/阴影/字体族，逐处替换间距会拉大 diff 且不影响方向判断，留到 M2 排版时一并做。

## 备选方案

- **纸墨乡野（暖纸 + 赭石，宋体标题）**：最有文旅的"慢"气质，但与暖米色占位图撞色、且个性偏弱。
- **徽派几何（冷白 + 朱砂，直角、无阴影）**：地域辨识最强，代价是直角+无阴影在密集列表里显得硬，且需要合规底图与高质量照片支撑。
- **数据图鉴（冷灰 + 深青，两级阴影）**：信息最清楚、最安全，但情绪最少，容易像通用工具。
- **上设计系统库（Element Plus / Naive UI 等）**：省下自研样式，但引入整套组件体积与既定视觉，与「一张地图 + 少量卡片」的形态不匹配，首屏预算（300 kB）已用掉 231 kB。
