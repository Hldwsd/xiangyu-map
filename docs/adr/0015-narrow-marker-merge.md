# 0015. 窄屏默认合并重叠地标

- 状态：已接受
- 日期：2026-11-23
- 决策人：B 实现，A 评审

## 背景

v0.1.0 的地标是软碰撞小球，桌面宽度下靠碰撞把密集点位轻轻推开；但 360–430dp 的手机屏幕上，球本身只有约 18px，推开后仍然互相压住，点击命中率低。

CHANGELOG 把「窄屏地标密度」列为 v0.1.0 已知问题。可选方向：

1. 缩小球/碰撞半径，让所有点都露出来；
2. 窄屏默认开「合并重叠标签」，聚成一个带数字的点，点击放大；
3. 只在用户手动打开合并时才合并，保持现状。

## 决策

**没有用户偏好时，窄屏默认合并。**

- 断点：容器宽度 `< 520px`；
- 窄屏聚合半径从 36px 提高到 **48px**，减少「数字标签旁边还挂着几颗球」的情况；
- 桌面默认仍不合并，保留每个项目单独点击；
- 用户手动关掉合并（localStorage `xy-merge-markers=0`）后，窄屏也尊重选择；
- 容器宽度未知（0）时按桌面处理，避免量尺寸前误开。

实现位置：

- `src/utils/map-defaults.ts`：是否默认合并；
- `src/components/map/cluster-sites.ts`：`clusterGapForWidth`；
- `src/views/HomeView.vue` / `src/components/map/AnhuiMap.vue` 消费。

## 为什么不选另外两条

| 方案            | 问题                                                   |
| --------------- | ------------------------------------------------------ |
| 缩小球/碰撞半径 | 球变小后触摸命中更差；360dp 上高密度区仍会叠           |
| 永远合并        | 桌面也看不到单点，损失「每个项目都能直接点」的核心体验 |
| 保持现状        | 手机上高密度区实际点不中，v0.1.0 已知问题不解决        |

## 代价

- 手机默认看到的是数字聚合点，不是每个项目一颗球；需要点一下放大；
- 用户如果从桌面（默认不合并）切到手机，已存的 `0` 偏好会继续生效，不会自动改；
- 只按初始 `innerWidth` 判断，旋转屏幕后不会自动切换；旋转后可用菜单手动切换；
- 新增两个纯函数与 4 个单测，不引入依赖。

## 验证

- `map-defaults.spec.ts`：390/360 默认 true，1024 默认 false，显式 `0`/`1` 优先，宽度 0 回退桌面；
- `cluster-sites.spec.ts`：360/430 → 48px，1024/0 → 36px；
- 390px Playwright 截图：地图出现 7/11/9 等聚合数字，不再是一团叠球；
- 桌面 E2E 保持 10 passed / 2 skipped；
- 单测 148/14 文件，构建 265.41 KB，入口 JS 256.59 KB。
