# 0017. 标识：采用设计稿位图，红 / 黑两版

- 状态：已接受
- 日期：2026-11-23
- 决策人：项目所有者（提供红、黑两版设计稿）

## 背景

版头的「落款印」一直是 CSS 画出来的朱砂方块 + 一个「徽」字（ADR 0008），站点没有真正的标识。项目所有者提供了同一构图的两版手绘印稿：红版 762×852、黑版 1094×1250，都是带纸纹与毛边的位图，没有透明通道。

其间做过一版 128 栅格的黑白矢量骨架（正方印面、平头刻线、长撇渐细）。结构成立，但笔锋、飞白与毛边在几何化之后损失明显，失去这次标识的主要价值。

## 决策

1. 标识以设计稿为准，不重绘字形。
2. 版头落款印改用红版透明图（`public/brand/logo-red.webp`），取代 CSS 方块；favicon / apple-touch 由同一红版生成方形纸底图。
3. 黑版作为单色资产随包（`public/brand/logo-black.webp`），用于一色印刷或浅底单色场景；当前界面没有用到它。
4. 纸底在导出时抠掉（alpha 由亮度反推），字是镂空的；版头里透出的是卡片自身纸色，不给图片加底色。
5. 分享图统一换用该标识：70 张站点分享图由 `make-og-images*.py` 读取 `design/logo/derived/logo-red-solid.png`（纸白字、印外透明）绘制；默认分享图 `public/og-cover.jpg` 没有生成脚本，标识是手工替换的。
6. 源图放 `design/logo/source/`，导出脚本 `design/logo/build-assets.py`，`public/brand/` 只放产物。

## 理由

- **笔锋是这版标识的全部价值**：粗细变化、飞白、毛边。矢量重绘在 128 栅格里基本留不住，做出来的骨架更像刀刻，和原稿不是一回事。
- **直接抠底 + 导出可以当天上站**：不用先解决字库、转曲、授权这一串问题。
- **红版回到 ADR 0008 的朱砂纪律**：先前只拿到黑版时，版头换成黑印，全站失去唯一的高饱和锚点，观感偏灰；红版把这一步收回来。
- **红黑两版各有用处**：红版上界面，黑版保一色印刷与浅底单色场景，不用临时再调。

## 后果

- **位图的固有代价**：16px 只剩色块；竖长比例 0.87–0.90 放进方形位（头像、App 图标）会左右留白，所以图标补了方形纸底；纸纹和毛边在缩放时会被重采样，做不到矢量那样每档都清晰。
- **透明版的字是镂空**：深色底会把「乡」吃掉。深色场景必须另出「纸白字」反白版；黑版同样是镂空字，不能当深底版用。
- **版头变高**：落款印从 2.6rem 方块变成 3.2rem 图片，品牌区约 +15px。
- **`--seal-red` 在版头不再被引用**；token 保留（未来别的落款、描边还可能用）。
- **不占打包体积**：`public/` 原样复制，logo 约 26 KB、图标合计约 50 KB，不进 JS 预算。
- 以后换图必须重跑 `build-assets.py`，不能手改 `public/brand/` 下的产物。

## 备选方案

- **128 栅格矢量重绘**（已做过骨架）：小尺寸最稳、体积最小，但丢笔锋；
- **只换 favicon、版头保留 CSS 朱砂印**：改动最小，但标识进不了主界面。
