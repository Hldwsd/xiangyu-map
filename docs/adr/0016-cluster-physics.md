# 0016. 合并标签也走软碰撞，并在合并/拆分时吸附

- 合并/拆分不做弹簧吸附，改成 280ms 的扇形缓动：拆分时多个新簇先从旧簇中心沿圆周散开再到位，避免「凭空出现」；
- 状态：已接受
- 日期：2026-11-23
- 决策人：B 实现，A 评审

## 背景

v0.1.0 有两套地标呈现：

- 不合并：每个项目一颗软碰撞小球，hover 会「带一下」，靠弹簧回位；
- 合并：相邻项目合成一个带数字的标签，点击放大。

合并模式此前是静态散点：没有小球碰撞、没有 hover 拨动，缩放导致簇合并/拆分时位置直接跳变。用户要求：

1. 合并标签状态也要有不合并标签的物理效果；
2. 合并/拆分时要有吸附的动态效果。

## 决策

合并模式的簇也用同一套 `BallState` 物理，但只作用于**簇节点**：

- 簇的 home 是成员经纬度均值投影到屏幕的位置；
- 簇之间做软碰撞，碰撞半径 30px（比单球 18px 大，因为数字标签更大）；
- hover 簇时同样「带一下」，弹簧拉回；
- 合并/拆分时先从旧位置出发，再被弹簧吸到新 home：
  - 拆分：新簇成员都来自同一个旧簇，所有新簇从旧簇位置出发；
  - 合并：新簇成员来自多个旧簇，从旧位置平均值出发；
  - 首次出现/减少动效：静默结算，不逐帧写 option；
- 首屏仍静默结算，避免重新引入 TBT 长任务；
- 拖动/缩放期间物理让路（沿用现有 `roamActiveUntil`）。

簇的稳定键是成员 id 排序后拼接（`markerClusterKey`），用来找回上一帧的簇；成员到屏幕位置的映射保留在 `clusterMemberPositions`，供下一次拆分/合并取起点。

## 为什么不选另外两条

| 方案                           | 问题                                                                |
| ------------------------------ | ------------------------------------------------------------------- |
| 只给合并模式加入场动画         | 不能解决 hover/碰撞；合并/拆分仍是跳变                              |
| 把簇也当作普通球，直接改经纬度 | 会偏离成员的几何中心，簇与真实位置对不上                            |
| 用 ECharts 自带 data 动画      | scatter 的 geo 坐标没有稳定的 item id/transition，合并/拆分时不可靠 |

## 代价

- 合并/拆分期间每帧 `setOption` 更新 `symbolOffset`，只持续约十几帧；首屏静默结算；
- 簇的碰撞半径大于单球，密集区可能比之前更散一点；
- 簇节点离开 home 最大 48px（沿用单球限制），不会推到不可理解的位置；
- 新增 `markerClusterKey` / `clusterStartPosition` 纯函数与 3 个单测；
- 首屏 JS 257.07 KB / 300 KB（86%），构建 265.90 KB，仍有余量。

## 验证

- `cluster-sites.spec.ts`：簇键与成员顺序无关；拆分从旧簇位置出发；合并取旧位置平均；无旧位置回退 home；
- 390px Playwright 截图：合并模式出现 2/5/7/19 等数字簇；连续放大后簇拆成更多小簇，页面无 console error；
- 现有桌面/移动 E2E 12 passed / 2 skipped；
- 单测 147/13（合并 #168 后为 151/14）。
