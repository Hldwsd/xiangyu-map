# 0006. 首页信息架构：全屏地图 + 顶部浮层

- 状态：已接受
- 日期：2026-11-19
- 决策人：负责人提出布局要求；A（Hldwsd）实现

## 背景

原先首页是「左地图 + 右列表」的两栏布局，顶部还有一条全站头部（品牌 + 导航），页脚一条说明。

问题：

- 打开页面第一眼看到的是一条 56px 的头部和一块 340px 宽的列表，地图只是左边的一栏；
- 头部、页脚、筛选卡、列表卡、地图卡——一屏里五层边框，「看地图」这件事被 UI 包围；
- 窄屏时地图被压到 66vh，搜索与筛选各占一行。

负责人要求：**打开就是全屏地图**，顶部一条全圆角搜索栏，搜索栏左边菜单按钮、右边筛选按钮。

## 决策

1. 首页改为**全屏地图**（`position: fixed; inset: 0`），地图铺满视口。
2. 顶部浮层 `TopBar`：`[菜单] [全圆角搜索栏] [筛选]`。
   - 菜单（左）：打开左侧抽屉 `MenuDrawer`，含品牌、项目列表入口、关于与数据说明；
   - 搜索（中）：全站唯一的搜索入口，带清除按钮；
   - 筛选（右）：打开右下浮层 `FilterPopover`（六个分类 + 城市 + 结果数），生效时按钮反色并挂角标。
3. 列表从常驻栏改为**按需抽屉** `SiteListSheet`：底部「列表 N」按钮或菜单里的「项目列表」打开，右侧卡片式、窄屏通栏。
4. 选中项目仍是浮卡 `SitePanel`：桌面右下、窄屏贴底，不遮挡顶部栏。
5. 分类 chip 与城市选择从首页常驻区移入筛选浮层；`CategoryFilter` 只负责分类，搜索归 `TopBar`。
6. 全站头部/页脚只在非首页渲染（`App.vue` 按路由判断）：首页属于「应用态」，详情页属于「阅读态」，后者保留头部与页脚。

## 理由

- **产品是地图产品**：第一眼应该是省域轮廓与地标，而不是侧栏。搜索与筛选作为浮层，随时可用但默认不占版面。
- **移动端与桌面同一套结构**：原来两栏在窄屏要重排成上下、地图高度还要特殊处理；改成浮层后，桌面与手机是同一套 DOM，只是浮层宽度与列数不同。
- **搜索前移**：原先搜索埋在筛选卡里，用户要「先看卡片再找输入框」；放到顶部胶囊后是最显眼的一级入口。
- **列表降级为抽屉**：22 条数据时列表很长，常驻会吃掉地图宽度；作为抽屉按需打开，还能在菜单里发现。

## 后果

- **首页失去全站头部**：品牌与「关于」只能在菜单里看到。详情页仍保留头部，两者观感不同——这是有意的「应用态 vs 阅读态」区分。
- **列表不再是首屏信息**：想按名字浏览要多点一次（列表按钮或菜单）。作为补偿，底部按钮直接显示当前结果数（`列表 22`）。
- **浮层需要处置遮挡与焦点**：菜单打开时锁页面滚动（`body.has-overlay`）、`Escape` 关闭、点击遮罩关闭；筛选浮层与菜单互斥（打开一个自动关另一个）。目前没有做完整的焦点陷阱，Tab 仍可能走到地图的语义列表——已知限制，M3 质量阶段再补。
- **`CategoryFilter` 的契约变了**：不再接收 `query`，搜索归 `TopBar`；相关测试同步改为 `TopBar` 的搜索测试。
- **深链/回退**：首页是全屏地图，选中项目仍是 store 状态而非路由，刷新丢失——与之前一致，M2 的「回退保持选中态」再处理。

## 备选方案

- **保留两栏、只把地图变宽**：改动最小，但仍是「UI 包围地图」。
- **底部 Tab 栏（地图 / 列表 / 关于）**：移动端常见，但桌面端退化成一条空荡的底栏，且搜索仍要单独找位置。
- **搜索放到菜单里**：更极简，但搜索是高频动作，藏进菜单等于取消它。
- **列表做成右侧可拖拽面板**：交互成本高（拖拽命中、吸附、触屏 vs 鼠标），收益不如一次点击打开。
