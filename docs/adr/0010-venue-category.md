# 0010. 分类契约扩展：新增「场馆」分类

- 状态：已接受
- 日期：2026-11-21
- 决策人：项目所有者（在数据线推进中明确要求「加上著名的博物馆、科技馆之类」）

## 背景

数据线推进到 60 条（data-round8）后，六分类（古镇 / 非遗 / 红色 / 自然 / 演艺 / 乡村）的覆盖缺口显露：安徽博物院、合肥科技馆、中国徽州文化博物馆、楚文化博物馆这类**室内展馆**无法归入任何现有分类——它们是文旅项目的真实组成，硬塞进「乡村」或「非遗」都是撒谎。

## 决策

1. **`SiteCategory` 新增「场馆」**：博物馆、科技馆、规划馆等室内展馆类项目归此类；
2. S1 圆线新增第七枚图标「柱廊立面」（山墙 + 三柱 + 台基，博物馆的通用立面，3 条 path）；
3. 分类色 `--cat-venue` 与其余六类同为墨色（单色纪律不变）；
4. 严格遵循既有扩散链：`SITE_CATEGORIES` → `CATEGORY_GLYPHS` / `CATEGORY_VARS` / `DEFAULT_PALETTE.category` / `CATEGORY_COLORS`（引用 DEFAULT_PALETTE，单源）/ store 的 `categoryCounts`，TS 的 `Record<SiteCategory, …>` 会在漏改处编译报错——本次靠它找齐了全部 6 处。

## 理由

- 「场馆」与六类并列后，安徽的头部文化场馆（国家一级博物馆 3 家 + 首座创新主题馆）首次可以按真实语义收录；
- 图标用「柱廊立面」而不是齿轮/原子：博物馆与科技馆共用一套立面语言，48px 下柱式轮廓最易辨认；
- 不引入颜色编码（`--cat-venue` 同墨色），形状仍是唯一编码通道（0004 纪律延续）。

## 后果

- **契约变更**：`SITE_CATEGORIES` 从 6 值到 7 值。所有 `Record<SiteCategory, …>` 结构必须同步——漏改会在 `vue-tsc` 处直接报错，这是契约安全网；
- 图例从「全部 + 6 类」变「全部 + 7 类」，图例行数 +1；
- **B 需知会**：数据校验枚举、图例、筛选、图标均随类型自动联动；若 B 的本地分支（如 data-round5）有引用旧枚举的代码，rebase 时会看到类型错误，按本 ADR 补键即可；
- 数据：首批收录 4 条场馆（安徽博物院、安徽创新馆、徽州文化博物馆、楚文化博物馆），总量 60 → 64。

## 备选方案

- **不改契约、把博物馆硬塞现有分类**：被否——语义撒谎，且后续每加一家场馆都在累积错误分类；
- **拆成「博物馆」「科技馆」两类**：被否——安徽头部场馆数量不足以支撑两类，图标也难区分，先用「场馆」合并档，量起来再拆。
