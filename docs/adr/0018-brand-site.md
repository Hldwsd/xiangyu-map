# 0018. 品牌页：独立 HTML 入口 + GSAP 滚动叙事

- 状态：已接受
- 日期：2026-11-23
- 决策人：项目所有者（发起）、实现方

## 背景

地图解决的是「查」，不解决「为什么值得查」。第一次来的人看到一张安徽省地图，
不知道这 70 个点是谁标的、凭什么可信、和别的旅游站有什么不同；首页也没有地方
放一段完整的叙事。2026-11-23 收到需求：给项目做一个网站，用 GSAP 做丰富的动效，
要能体现设计感，技术不限。

约束来自两处：

- 主站首屏 JS 预算 300 KB（gzip），当前已用到 79%，GSAP + ScrollTrigger 再加进去会顶到红线；
- 主站是 fixed 全屏地图 + ECharts，滚动叙事（pin、横向滚动、逐字显墨）和它的布局模型天然冲突。

## 决策

1. **品牌页是同一 Vite 构建的第二个 HTML 入口**：`brand/index.html` → 产物 `dist/brand/index.html`，
   线上地址 `/xiangyu-map/brand/`。不是 SPA 路由。
2. **技术栈：原生 TypeScript + gsap + ScrollTrigger + Lenis**，不引入 Vue 组件，也不复用 ECharts。
3. **数据同源**：地图上的 70 个点、16 个市、7 个分类全部从 `src/data/sites.ts` 派生，
   品牌页不另抄一份数字。
4. **几何预生成**：`scripts/build-brand-geo.mjs` 把省界、16 市轮廓、9 片水面、长江淮河
   投影并抽稀成 SVG path，写进 `src/brand/geo.generated.ts`；页面运行期只画 SVG。
5. **视觉延续纸本墨线**：纸底、墨线、金色点睛、朱砂落款；字体用系统宋体栈，不引外部 CJK 字体。
6. **动效可关闭**：`prefers-reduced-motion: reduce` 时跳过入场、滚动 scrub、pin 与平滑滚动，
   直接呈现最终排版。
7. **主站菜单加入口**（「品牌页 · 一纸山河」），品牌页 CTA 回到地图，两边互相可达。

## 理由

- **独立入口而不是懒加载路由**：品牌页有自己的全局滚动、fixed 顶栏、全屏 pinned 段落，
  与主站的 fixed 地图壳层抢滚动控制权；独立入口还让主站首屏完全不下载 GSAP（`bundle:size` 不受影响）。
- **原生 TS 而不是 Vue**：这一页的工作是逐帧改写 DOM/SVG（描边、拆字、pin），
  没有列表复用与状态流，Vue 的响应式在这里只增加一层抽象。
- **数据同源**：品牌页写死「70 处」而地图涨到 72，是最难向读者解释的一类错。
- **预生成几何**：运行期拉 250 KB GeoJSON 只为画一张静态 SVG 不划算；抽稀后的生成文件约 65 KB，
  且省掉一次 Clustering/Projection 的心智负担。
- **系统字体**：中文字体包动辄数 MB，品牌页首屏的观感不该赌在字体下载上。

## 后果

- 构建多一个入口；资源与链接必须走 `import.meta.env.BASE_URL`（背景书法、封面、`/site/<id>`、回到地图），
  否则子路径部署会 404。
- 品牌页的叙述性文案与主站是两份，需要人工保持口径（数字已由同源解决，文字仍需维护）。
- E2E 只做冒烟（节点数量、无运行时错误、锚点可达），动画节奏靠人工验收；
  `e2e/brand.spec.ts` 覆盖入口可打开、70 点/16 城/7 类/6 面板渲染。
- 「品牌页」成为需要同步维护的第二个界面：改视觉语言（tokens、标识）时要两边一起看。

## 备选方案

- **作为 `/story` 路由放进 SPA**：省一个构建入口，但要么把 GSAP 打进主包、要么再拆一个懒加载 chunk；
  全屏滚动叙事与主站 fixed 地图布局、Pinia/ECharts 生命周期相互干扰，收益不抵成本。
- **独立仓库 / 子站**：隔离最彻底，但部署、PR 预览、依赖升级要再维护一套流水线；本次只多一个页面，不值得。
- **纯 CSS 动画 / GSAP 仅做点缀**：做不出逐字显墨、横向 pin、滚动进度这类连续叙事，
  也违背「使用 GSAP」的明确要求。
