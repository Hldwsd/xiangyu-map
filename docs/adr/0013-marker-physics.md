# 0013. 地标改用软碰撞小球，而不是圆环 + 引线

- 状态：已接受（交互方向由负责人拍板；真机验收仍挂在 #16）
- 日期：2026-11-22
- 决策人：A（Hldwsd）实现，B 记录

## 背景

安徽东南部（黄山、歙县、黟县一带）点位密，默认视野下多个地标会落在同一屏幕位置。最初是静态针形散点，重叠时后画的点直接盖住先画的点，点击命中率低。

#139 先试了「小圆环 + 引线 + 真实位置锚点」：把重叠点沿固定方向散开，用引线指回真实坐标。它解决了命中与可见性，但视觉上多出一圈引线，密集区像蛛网；负责人明确要求改成「小物理球」。

## 决策

地标渲染改为**带软碰撞的小球**：

- 同一处挤着的球互相施加软碰撞，停住时仍允许互相压住——不是整齐圆环，也不是完全叠死；
- 悬停时球被「带一下」：力度按最近一次 mousemove 的速度算（min(6, speed×2.2)），指针停住超过 150ms 或速度 <0.15px/ms 不触发；同一颗球 260ms 内只带一次；
- 点击沿用选中态（放大 + 金环），其它球继续维持软碰撞；
- 每帧是力模型：回位弹簧 + 软接触力（重叠越深推力越大），速度乘阻尼，接触时沿法向吸收接近速度；离 home 不超过 48px，密集区不会越推越散；
- 停稳判定：速度与每帧位移都 <0.02 连续 15 帧才冻结，不做固定帧数截断；地图缩放/拖动时按 home 位移整体平移，保留相对偏移，不重置成原点；
- 打开「合并重叠标签」时物理循环停止，走原合并逻辑。

实现拆在 `src/components/map/marker-physics.ts`，渲染仍由 `anhui-map-option.ts` 消费；不新增 ECharts 实例。

## 为什么不选另外几条路

| 方案                     | 问题                                                           |
| ------------------------ | -------------------------------------------------------------- |
| 静态针形散点，重叠就叠着 | 命中率低，密集区后面点位永远点不到                             |
| 圆环 + 引线（#139）      | 命中解决了，但密集区引线过多，视觉噪音大；负责人否决           |
| 只做聚合、不散开         | 聚合点能点，但放大前后要换一套交互，且默认视野看不到单点       |
| 完全自由物理             | 球会被推离真实位置，密集区越推越散，和「地图上的位置可信」冲突 |

## 代价与风险

- 每帧有物理循环（70 颗球），需要真机 FPS 与点击命中率复测（#16）；当前只有单测，没有真机帧率数据；
- 球停住时仍可能互相压住，密集区点击要靠选中态与列表兜底；键盘路径仍走「项目列表」抽屉，不依赖球本身；
- 悬停「带一下」属于动效，**已由 #151 关闭**：reduce 下不播入场动画、不拨球；
- 首屏入口 JS 254.64 KB / 300 KB（85%），物理逻辑本身不大，但后续加功能要盯预算。

## 验证

- `src/__tests__/marker-physics.spec.ts`：推开的球能回位、双球软碰撞停在碰撞半径内、五球同点不发散、nudge 后可回位；
- #147 手工验证：缩放 1→3 倍再拖动，38 颗有偏移的球总偏移量保持 252.4，徽州古城偏移 (-3, -8.3) 全程不变；
- 141 用例、六闸门通过（含覆盖率与 E2E），构建 gzip 263.38 KB，入口 JS 254.64 KB；
- 真机 FPS、移动端触摸命中仍待 #16 复测；reduced-motion 已由 #151 关闭。

## 后续

若真机验收发现帧率或命中不达标，优先调小物理循环频率/碰撞迭代次数，或只对「同屏距离 < 阈值的球」启用物理；不要退回圆环 + 引线。
