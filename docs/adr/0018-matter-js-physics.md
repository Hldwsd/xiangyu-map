# 0018. 地标小球改用 matter-js

- 状态：已接受（实验性替换，保留回退可能）
- 日期：2026-11-23
- 决策人：A

## 背景

地标的「小物理球」从 #142 起是手写力模型：弹簧回位 + 软接触力 + 阻尼，几十行、无依赖。
问题在于参数是靠手感调的，簇（合并标签）也要复用同一套力；后续想加旋转、静摩擦、
不同半径的球时，手写模型每加一项都要自己推导。

## 决策

用 **matter-js** 的 `Engine + Bodies.circle + Constraint` 替换手写求解，接口保持不变
（`stepBalls` / `nudgeBall` / `BallState`），组件仍只读位置写 `symbolOffset`。

- 每颗球一个圆形刚体，半径取 `collide / 2`，`frictionAir = 1 - damping`；
- 回位用 `Constraint`（点 A = home，body B = 球，stiffness ≈ `spring / 2`，damping 0.08）；
- 外部瞬移（缩放平移、补间）通过「刚体位置与球位置偏差 > 1.5px」识别，直接 `Body.setPosition` 并清零速度；
- 引擎按 `balls` 数组缓存（`WeakMap`），数组换代即重建 world；`nudgeBall` 直接给刚体加速度。

## 理由

- 手写模型调参成本高，matter 的约束/碰撞求解更稳定，悬浮与停手后的静止判定更好写；
- 测试（151 个）不改断言即可通过，行为与旧模型一致：推开到约一个碰撞直径内、仍重叠；
- 体积可接受：入口 JS 258.06 → **261.59 KB**（gzip +3.5 KB），预算 300 KB；
- 移动档 Lighthouse 本地 **80**（TBT 240ms），与替换前持平。

## 代价

- 多一个运行时依赖（matter-js 0.20）；本仓库是单页地图，依赖只影响入口包；
- 引擎内部有速度状态，外部改坐标必须同步（已用 1.5px 偏差判定处理）；
- 结算不能在缩放结束同步跑满帧：改成「无重叠直接落位，最多 24 步」，避免长任务。

## 备选

- **保留手写力模型**：零依赖、参数完全可控，但每加一种行为都要重新推导；
- **自写 Verlet/位置约束**：体积更小，但碰撞与约束稳定性不如 matter，收益不明显；
- **只在合并模式用 matter**：两套求解并存，维护成本更高，不采纳。
