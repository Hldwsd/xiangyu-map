# M1 地图内核：命中率 / 聚合 / 手势复测（2026-11-21）

> 对应 Issue #16。测试环境：本地 dev（`localhost:5178`）、ego 浏览器 1444×825、
> 42 条数据（data-round6）。脚本按「每次点击前重载页面」的方式跑，避免上一次选中态
> 把地标从簇里拆出来影响结果。

## 结论

| 项                     | 结果                                                       |
| ---------------------- | ---------------------------------------------------------- |
| 单点命中率（默认视野） | **17/17 = 100%**                                           |
| 聚合点点击             | **9/9** 都会放大（zoom 1 → 2）                             |
| 滚轮缩放               | 10 次 −180 滚轮 → zoom **2.59**（原生 roam，跟手）         |
| 双指缩放（触屏模拟）   | 1 → **1.33**，能放大但比手指比例保守（ECharts 原生 pinch） |
| 缩放期间长任务         | 10 次滚轮期间仅 **1 个 63ms** 长任务                       |

## 复测中定位并修掉的问题：精选钉互相压住

修前单点命中率是 **9/11**，两处误点：

- 点「黄山风景区」→ 选中「宏村」
- 点「西递」→ 选中「宏村」

原因：本期精选（黄山/宏村/徽州古城）为了「推荐位不被折叠」被无条件从簇里拆出来单独画，
但它们彼此只差 **28px（黄山↔宏村）、15px（宏村↔西递）**，42px 的金环钉直接叠在一起，
点在重叠区就选中最上层那颗。

修法（本次 PR）：精选**只在独占一个簇时**才单独绘制；和别的点挤在 36px 内时留在簇里，
簇描**金环**提示「这簇里有精选」。修后三颗合成一个「3」的金环簇，点击放大后正常分开，
单点命中率回到 **17/17**。

## 方法

1. 用 `chart.convertToPixel({ geoIndex: 0 }, 经纬度)` 取每颗地标/簇的屏幕坐标；
2. 每次点击前 `page.reload()`，等待地标重算完成；
3. 用 CDP `Input.dispatchMouseEvent` 在坐标上按下/松开（真实命中区，不走 DOM 事件）；
4. 读 `.panel__title` 与预期项目名比对；聚合点则看 `geo.zoom` 是否上升、簇是否拆开；
5. 长任务用 `PerformanceObserver({ type: 'longtask' })` 统计滚轮缩放窗口内的阻塞。

## 已知局限

- **FPS 没测出可信值**：ego 浏览器窗口被遮挡时 `requestAnimationFrame` 会被节流
  （实测缩放要 ~840ms 才跳到新值），所以只报了长任务，没有报 FPS。要真实 FPS 需要在
  前台窗口里手动跑一次，或接 Playwright headed 模式。
- **双指缩放比例偏保守**：手指距离 100 → 250（2.5×）只换来 zoom 1 → 1.33；这是 ECharts
  原生 pinch 的增量算法，不是 bug，但如果觉得「捏不动」可以调 `scaleLimit` 或换成逐帧锚定。
- 窄屏（<1200）未单独跑命中率；地标尺寸不变，理论上一致。
