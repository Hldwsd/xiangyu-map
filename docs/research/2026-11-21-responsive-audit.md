# 窄屏与三档响应式实测（2026-11-21）

> 目的：M2 要求「响应式：≥1440 / 768–1439 / <768 三档布局」。这份记录回答两个问题：
> 现在实际是什么行为、和规划写的断点是否一致。
>
> 方法：在 `pnpm preview` 的产物上，用 CDP `Emulation.setDeviceMetricsOverride` 逐档设视口，
> 在**同一次脚本调用内**完成「设视口 → 等 350ms → 量元素 → 截图」，避免跨调用时视口被还原。

## 1. 实测结果

| 视口                 | 横向溢出   | 右侧栏          | 边缘标签                         | 地图            |
| -------------------- | ---------- | --------------- | -------------------------------- | --------------- |
| 375×667（手机竖屏）  | 0          | `display: none` | 左「分类」30×58、右「城市」30×58 | 375×667，占满   |
| 667×375（手机横屏）  | 0 / 纵向 0 | `display: none` | 左 30×58                         | 667×375，占满   |
| 768×1024（平板竖屏） | 0          | `display: none` | 左右各 32×62                     | 768×1024，占满  |
| 1024×768（平板横屏） | 0          | `display: none` | 左右各 30×58                     | 1024×768，占满  |
| 1440×900（桌面）     | 0          | 323×784         | 宽高归零（不渲染）               | 1440×900，占满  |
| 1920×1080（大屏）    | 0          | 364×950         | 宽高归零                         | 1920×1080，占满 |

三个关键行为：

1. **窄屏不靠缩，靠换形态**：<1200 时不压缩地图，而是隐藏右侧栏、改用左右两条竖排「分类 / 城市」边缘标签；
2. **宽屏加的是侧栏，不是边距**：≥1200 时右侧栏 323px 出现，边缘标签退场；
3. **没有横向溢出**：六个视口 `scrollWidth - innerWidth` 全部为 0。

## 2. 与规划的口径差异

| 来源                      | 断点                                                                                                                                                     |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `docs/PROJECT_PLAN.md` M2 | ≥1440 / 768–1439 / <768 三档                                                                                                                             |
| 代码实际                  | 主要断点 **1200**（`HomeRail.vue`、`HomeView.vue` 的 `width <= 1199px`），另有 900（地图）、720（详情页）与两条高度查询（`max-height: 760px` / `820px`） |

也就是说：规划写的是三档、以 1440 为桌面起点；实现是**以 1200 为桌面起点**，并且额外按高度与详情页宽度各有一档。

不建议直接改代码去凑 1440——1200 是这轮的视觉决策（[ADR 0008](../adr/0008-rail-vertical-brand.md) 之后版头改为竖排题字、会随视口缩放），改断点会连带影响版头与右栏的排版。建议**把规划里的三档描述改成实际断点**，并在 ADR 里记一句「响应式按 1200 分档」，避免下一个人照着 1440 去调。

## 3. 没覆盖到的

- **真机触摸**：CDP 的 `mobile: true` 只影响视口与 meta，不等于真机手势；双指缩放已由 A 在 #46 用触摸模拟验证过，但 iOS Safari 的橡皮筋与安全区没测；
- **iOS 安全区（`env(safe-area-inset-*)`）**：代码里没有相关适配，刘海屏横屏时顶栏可能压到状态栏；
- **超窄（320px）**：未测，主流行手机最小 360，影响有限；
- **动态字体放大**：浏览器 200% 缩放下布局未验。

## 4. 复现

```bash
pnpm build && pnpm preview --port 4173
# 然后用 CDP Emulation.setDeviceMetricsOverride 逐档设宽高，
# 量 document.documentElement.scrollWidth 与 .anhui-map / [class*="rail"] / .edge-tab--left 的 getBoundingClientRect
```
